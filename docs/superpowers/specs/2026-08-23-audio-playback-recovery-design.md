# 发音播放恢复设计

## 问题与根因

当前复习页在自动发音和手动「播放本组」时可能完全无声。已确认三个直接原因：

1. 词典服务的部分词条不提供音频 URL。
2. 已返回的词典音频 URL 也可能返回 5xx 或播放失败。
3. 当前控制器仅在 URL 缺失时启用浏览器语音；URL 存在但播放失败时只返回 `needsUserGesture`，页面没有处理该结果。浏览器语音不存在时也被误判为已开始播放。

## 目标

建立可恢复的三级播放链：

1. 优先播放词典真人音频。
2. 真人音频缺失、加载失败或播放失败时，自动改用浏览器英语语音。
3. 浏览器因用户激活策略拒绝自动发音时，提供一次性手动解锁入口。

不接入付费 TTS API，不新增音频状态栏，不改变现有播放按钮布局。

## 音频控制器

### 统一结果

每个播放方法返回明确结果：

- `playing`：真人音频或浏览器语音已开始。
- `needs-user-gesture`：必须由用户点击后重试。
- `unavailable`：真人音频和浏览器语音均不可用。

页面不再忽略播放结果。

### 真人音频降级

- `HTMLAudioElement.play()` reject 时调用浏览器语音。
- 音频元素触发 `error` 时也调用浏览器语音，覆盖 URL 在 `play()` 之后才加载失败的情况。
- 降级前清理失败的音频实例，保持任一时刻只有一个声源。
- 当前单词循环在语音结束后继续该词；List 循环在语音结束后进入下一词；表格行发音结束后停止。

### 浏览器语音能力

`SpeechPort.speak` 改为异步返回启动状态，不再静默返回：

- `speechSynthesis` 或 `SpeechSynthesisUtterance` 不存在时返回 `unavailable`。
- `SpeechSynthesisUtterance.onstart` 触发时返回 `playing`。
- `SpeechSynthesisUtterance.onerror` 为 `not-allowed` 时返回 `needs-user-gesture`；语音、语言或合成能力不可用时返回 `unavailable`。
- 同一个 generation token 控制后续循环，切词、切口音、切表格或离开页面后，旧回调不能重启播放。

## 页面恢复交互

- 自动发音返回 `needs-user-gesture` 时，在当前单词内容区显示轻量按钮「点击页面开启发音」。
- 提示不使用 toast、弹窗、badge 或底部播放状态栏。
- 用户点击后立即重播当前单词；成功后移除提示，并恢复自动循环。
- 播放结果为 `unavailable` 时，同一位置显示「当前浏览器无法发音」，不进行无限重试。
- 用户手动点击「播放本组」时也处理上述结果，不再无条件显示为正在播放。
- 单词翻页、口音切换和视图切换时清除上一个词的恢复提示，并根据新的播放结果更新。

## 异常与竞态

- 仅当播放请求仍属于当前 generation 时才能降级或继续。
- 旧音频在用户切换内容后发生 reject 或 `error`，不得触发新的语音。
- 连续点击播放时，新请求通过 generation 使旧请求失效。
- `pause()` 必须同时清理音频 `onended`/`onerror`、停止音频、归零时间并取消语音合成。

## 测试与验收

- 有效真人音频仍按原逻辑播放。
- `play()` reject 后启用浏览器语音。
- 音频 `error` 后启用浏览器语音。
- 浏览器语音缺失时返回 `unavailable`。
- 旧 generation 的失败不得启动新语音。
- 自动播放需要手势时显示解锁提示，点击后重试并在成功后隐藏。
- 播放本组失败时不得留在虚假的「暂停播放」状态。
- 原有单词循环、List 循环、表格行播放、切词停止与离页清理测试继续通过。
- 完整单元测试、类型检查、生产构建和端到端流程通过。

## 非目标

- 不代理或缓存第三方词典音频。
- 不调用 OpenAI 或其他付费 TTS 服务。
- 不修改词条数据库 Schema。
- 不新增全局播放器或持久化播放偏好。
