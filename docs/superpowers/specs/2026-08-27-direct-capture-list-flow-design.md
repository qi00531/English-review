# Word Journal 直接收录到今日 List 设计

日期：2026-08-27  
状态：已确认

## 1. 背景与目标

当前网页手动记录和浏览器划词会先把内容放入“待整理”，并要求用户完成当天复习后才能生成新的 List。这增加了一次整理操作，也把“随手记录”与“按计划复习”错误地绑定在一起。

本次调整将记录和复习解耦：网页手动输入与浏览器划词确认后都直接进入当天的同一个 List；即使仍有到期复习，用户也可以继续记录。今日 List 从第二天起进入正式复习计划。

核心目标：

- 取消“待整理”这一用户可见阶段。
- 让网页输入与扩展划词共用同一条保存链路。
- 保留复习优先级，但不再以复习完成状态限制记录。
- 安全迁移已有待整理数据，不丢失内容或重复生成 List。
- 在 AI 或本地保存失败时提供可理解、可重试且脱敏的错误信息。

## 2. 范围

### 2.1 包含

- 手动记录始终可用，保存后直接追加到今日 List。
- 扩展划词预览确认后直接追加到今日 List。
- 同一自然日的多次保存复用同一个 List。
- 保留重复检测与用户明确选择“再次加入”的能力。
- 自动迁移已有 `captureDrafts` 待整理记录。
- 移除待整理页面、首页待整理数量和复习门槛。
- 补充面向用户的错误原因、重试和脱敏错误详情。
- 兼容旧待整理路由，访问时安全返回首页。

### 2.2 不包含

- 句子、截图、OCR 或通用知识卡片收录。
- 桌面系统全局划词。
- 云同步、账号体系或跨设备迁移。
- 修改现有遗忘曲线间隔。
- 删除旧 IndexedDB 表；本阶段仅停止新写入并保留兼容性。

## 3. 产品规则

### 3.1 今日 List

- 日期以用户设备的本地自然日计算，不使用 UTC 日期截断。
- 当天首次成功保存时创建今日 List，并一次性创建该 List 的复习节点。
- 当天后续通过网页或扩展保存的内容全部追加到该 List，不再创建新 List，也不重复创建复习节点。
- 今日 List 的首次正式复习从第二天开始；当天不会成为到期复习任务。

### 3.2 记录与复习解耦

- 存在未完成的到期 List 时，用户仍能打开“记录今天所学”并保存。
- 从历史页提前打开今日 List 或未来到期 List 只属于自由练习。
- 自由练习不得更新复习节点、首页正式进度或连续学习天数。
- 只有从正式到期任务入口完成 List，才能完成对应的计划节点。

### 3.3 重复内容

查重值沿用标准化英文：统一大小写、去除首尾空白并合并连续空格。

- 若今日 List 已存在该内容，提示“今日 List 已存在该内容”。
- 若历史 List 已存在，提示“List N 已存在该内容”。
- 默认不写入重复记录；用户明确选择“再次加入”后才跳过重复保护。
- “再次加入”仅影响当前保存，不改变之后的默认行为。

## 4. 架构与组件边界

采用统一的直接写入方案，不保留隐藏式待整理流程，也不允许扩展绕过数据仓库直接操作表。

```text
网页手动记录 ─┐
              ├─ Capture/List Application Service
扩展划词确认 ─┘       ├─ validate and normalize
                      ├─ detect duplicate
                      ├─ appendToDailyList(localDate)
                      └─ return List identity
                                  │
                          Learning Repository
                                  │
                              IndexedDB
```

各模块职责：

- **采集适配层**：网页表单或浏览器选区只产生统一的补全结果，不决定 List 与复习计划。
- **应用服务**：负责本地日期、校验、查重、重复覆盖意图和错误映射。
- **学习仓库**：在单一事务中查找或创建今日 List、创建必要的复习节点并写入 Entry。
- **迁移器**：一次性把旧待整理记录原子地转换为 Entry，业务界面不依赖它。
- **界面层**：只展示保存结果、重复确认和错误状态，不直接读写数据库表。

保存成功返回 List 的 `id` 与 `listNumber`，网页和扩展统一显示“已加入 List N”。

## 5. 数据流

### 5.1 网页手动记录

1. 用户在任意复习状态下进入“记录今天所学”。
2. 现有补全流程生成音标、完整中文释义和一个常见义例句。
3. 应用服务获取本地日期并执行查重。
4. 无重复或用户选择“再次加入”后，仓库原子地追加到今日 List。
5. 页面显示“已加入 List N”，随后沿用现有保存后导航行为。

### 5.2 浏览器划词

1. 用户选择英文单词或最多八词的短语并点击 W 或右键入口。
2. AI 补全成功后显示可编辑预览。
3. 用户确认时才执行查重和保存。
4. 保存成功显示“已加入 List N”；不再生成待整理记录。
5. 主页面是否打开不影响收录。

### 5.3 并发保存

“查找今日 List—必要时创建—追加 Entry”必须处于同一 IndexedDB 事务。两个入口几乎同时保存时，数据库的唯一 `createdDate` 约束与事务共同保证只有一个今日 List；冲突方重新读取该 List 后追加内容。

## 6. 旧待整理数据迁移

迁移在应用初始化后运行，且必须满足以下规则：

- 只迁移结构完整且状态为 `ready` 的旧记录。
- 在一个事务中查找或创建升级当天的 List、写入全部 Entry、创建必要复习节点并删除已迁移记录。
- 任一步骤失败时整个事务回滚，旧记录仍然存在；下次启动可以安全重试。
- 迁移不执行交互式查重。旧待整理中的每条记录代表用户已确认的收录意图，因此全部保留；事务原子性保证失败重试不会额外复制。
- 非 `ready` 或结构异常的旧记录不删除、不计入界面数量，并继续包含在本地备份快照中，避免静默丢失。
- 新版本不再调用 `saveCaptureDraft`；兼容表暂时保留，待后续独立的数据清理版本处理。

## 7. 界面与交互

### 7.1 首页

- 有到期复习时，复习任务保持页面主操作。
- 在复习任务下方提供较弱的文字入口“记录今天所学”，始终可点击。
- 当日正式复习全部完成后，“记录今天所学”恢复为现有绿色主按钮。
- 移除待整理入口、数量、徽标及相关说明，不增加新的卡片或仪表盘元素。

### 7.2 手动记录页

- 删除基于到期数量的路由门槛，记录页直接渲染。
- 保存按钮的加载、重复确认与成功反馈保持单一主操作。
- 成功信息明确显示目标 List 编号。

### 7.3 扩展浮层

- 保留英文、音标、中文释义和例句的可编辑预览。
- 主操作由“加入待整理”改为“加入今日 List”。
- 重复时保留“再次加入”次级操作。
- 成功后短暂显示“已加入 List N”再关闭，不展示待整理状态。

## 8. 错误处理

AI 补全或数据库保存失败时，不写入残缺 Entry，并保留当前输入或选词供用户重试。

用户可见错误按类型映射：

- 网络不可达或本地服务未启动；
- API 认证失败；
- 请求过于频繁；
- 模型不存在或不可用；
- 选择内容格式不受支持；
- AI 返回格式异常；
- 本地数据库写入失败；
- 服务暂时异常。

错误界面提供“重试”和“复制错误详情”。复制内容仅包含错误类型、HTTP 状态码、请求阶段与脱敏后的简要信息，不包含 API Key、Authorization 请求头、完整供应商响应、网页上下文或技术堆栈。

## 9. 路由与兼容行为

- 删除主导航和首页对待整理页面的入口。
- 旧待整理 URL 不渲染空页面，统一重定向到首页。
- IndexedDB 继续声明旧表，确保现有用户升级时能够读取和迁移数据。
- 备份与恢复格式暂时保留 `captureDrafts` 字段，避免旧备份无法恢复。

## 10. 验收标准

- 存在未完成到期 List 时，仍可进入手动记录页并成功保存。
- 同一天通过网页和扩展多次添加，最终只有一个 List，且所有内容均在其中。
- 本地零点之后的首次保存进入新的日期 List。
- 今日 List 当天不出现在正式到期任务中，第二天才开始复习。
- 历史页提前练习不改变计划完成状态、今日进度或连续学习天数。
- 重复项默认不保存，用户明确选择后可再次加入。
- 划词保存成功明确显示目标 List 编号。
- 旧待整理数据成功迁入升级当天的 List，失败重启不会丢失或重复。
- AI、网络、认证、限流、模型及数据库错误均显示脱敏原因并可重试。
- 待整理界面与数量提示消失，旧 URL 能安全返回首页。
- 网页和扩展现有发音、复习模式、历史、设置与划词触发能力不回归。

## 11. 测试策略

- **领域与仓库单元测试**：本地日期、每日单 List、复习节点只创建一次、并发追加、重复覆盖和事务回滚。
- **迁移测试**：正常批量迁移、空队列、故障回滚、重试幂等、异常旧记录保留和备份兼容。
- **应用服务测试**：手动输入与扩展消息共用保存规则，返回正确 List 编号。
- **UI 测试**：首页主次操作、无记录门槛、无待整理入口、重复确认、成功反馈和错误详情脱敏。
- **路由测试**：旧待整理 URL 重定向首页。
- **扩展契约测试**：Manifest V3、content script、service worker、右键入口和构建产物保持有效。
- **回归测试**：正式复习完成、历史自由练习、发音、表格模式、单词模式、备份与恢复。
- **人工验证**：Chrome 与 Edge 中真实划词、真实 AI 服务、跨本地零点行为和扩展重新加载。

自动测试与构建通过仅证明代码路径和产物通过验证，不等同于真实供应商 API、浏览器安装、系统声音和人工视觉验收已完成；交付时分别报告证据。

## 12. 后续事项

旧待整理表的物理删除、通用知识内容、截图/OCR、桌面全局划词、自动主题聚合和云同步均属于后续独立设计，不纳入本次实施。
