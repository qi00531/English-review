## README 信息结构

### 1. 产品首屏

- 居中的产品名 `Word Journal`。
- 一句话定位：本地优先的英语输入与间隔复习手账。
- 一句补充说明：把每天学到的单词和短语整理成 List，并按固定节奏重新出现。
- 首页截图。
- 四个克制的产品/技术标签。

### 2. 产品介绍

用一到两段解释产品解决的问题：学习内容容易分散、复习时机难以坚持、录入释义与例句成本高。强调产品通过每日 List、明确的复习节奏和本地数据存储降低执行成本。

### 3. 学习流程

以四个连续步骤说明真实使用路径：

1. 输入今天学到的英文单词或短语。
2. 词典与 AI 补全中文义项、音标、例句和可用音频信息。
3. 当天内容形成一个 List，并进入 D+1、D+2、D+4、D+7、D+15、D+30 复习计划。
4. 完成当天到期 List 后继续记录新内容，并积累连续学习天数。

### 4. 核心能力

- 每日 List 与当天复习门控。
- 艾宾浩斯式固定间隔复习计划。
- 只输入英文即可获得内容补全，且保存前可以编辑。
- 单词模式与表格模式。
- 完整、只看英文、只看中文三种显示方式。
- 单词模式自动朗读当前词；表格模式手动循环播放当前 List。
- 历史复习计划、手动重练和 List 内容管理。
- IndexedDB 本地保存、JSON 导入导出和恢复前安全备份。

### 5. 复习节奏

单独展示 `D+1 → D+2 → D+4 → D+7 → D+15 → D+30`，并说明同一天到期的多个 List 会共同出现在今日任务中。

### 6. 快速开始

- 前置要求：Node.js 20+ 与 Corepack。
- 提供依赖安装、复制 `.env.example`、启动前后端的完整命令。
- 说明 Vite Web 与本地 Hono API 的职责，API 默认监听 8787 端口。
- 不展示任何真实 API Key。

### 7. AI 与词典配置

- 解释 `DICTIONARY_BASE_URL`、`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`、`PORT`。
- 说明兼容 OpenAI Chat Completions 的服务可接入。
- 说明词典无结果时回退到 AI。
- 强调密钥只由服务端读取，不得使用 `VITE_*` 暴露或提交到仓库。

### 8. 数据与隐私

- Lists、词条、复习节点和设置保存在当前浏览器 IndexedDB。
- 无账号、无默认云同步。
- 只有当前需要补全的英文内容会发给词典/AI，历史库不会整体上传。
- 清除站点数据或更换浏览器会导致本地记录不可用。
- 建议定期导出 JSON；恢复前应用会先下载当前数据备份。

### 9. 技术架构

以紧凑列表说明：

- React 19 + TypeScript + React Router。
- Vite 前端构建。
- Hono 本地 API 服务。
- Dexie + IndexedDB 本地数据库。
- date-fns 处理日期。
- Vitest + Testing Library 单元/组件测试。
- Playwright 端到端测试。

### 10. 项目结构

只展示 `src/app`、`src/features`、`src/domain`、`src/db`、`src/audio`、`src/ui`、`server`、`tests/e2e`、`public/assets` 等关键目录及其职责，不罗列全部文件。

### 11. 测试与构建

提供 `test`、`typecheck`、`build`、`test:e2e` 命令，并说明首次缺少 Chromium 时使用 Playwright 安装命令。

### 12. 当前边界

明确说明当前版本：

- 面向本地桌面浏览器使用。
- 没有账号和跨设备同步。
- 不依赖移动端或浏览器扩展。
- 发音质量受可用音频源和浏览器语音能力影响。
